🔗 订阅（webcal）

把当前订阅源变成一个可长期订阅的日历地址：日历 App 会按自己的节奏自动重新拉取，不必每次手动导出。链接由 Cloudflare 上的 /api/rss-to-ics 实时把订阅源转成 ICS。

webcal —— iPhone / iPad / macOS / Outlook 直接点这个

📱 各端怎么添加 + 注意事项

iPhone / iPad：设置 → 日历 → 账户 → 添加账户 → 其他 → 添加已订阅的日历 → 粘贴链接。

macOS 日历：文件 → 新建日历订阅 → 粘贴链接 → 选「自动刷新」。

Google 日历：左下「其他日历」＋ → 通过网址添加 → 粘贴 https 链接。

Outlook：添加日历 → 从 Internet 订阅 → 粘贴链接。

⚠️ 订阅内容直接从订阅源派生，不包含你在上面表格里手工改的内容；要手工改就用「📥 导出 ICS」。

⚠️ 刷新时机由日历 App 决定（Apple 较勤、Google 约 12–24 小时），不是实时；端点已用缓存保护源站。

📄 备份 / 定时清单长什么样

⬆️ 导出备份：得到 { version, feeds: [{ name, url, tz, dur, title, uid, limit, remind, ev }] }；换电脑 / 换浏览器时用「⬇️ 导入备份」恢复（按 url 合并，同名以导入为准）。

📋 复制定时预热清单：得到 { "urls": [ ... ] }，整段替换仓库里 .github/warm-rss.json 的内容即可 —— GitHub Actions 会按它每 2 小时自动预热。

列表每行的按钮：📥 载入到上面的编辑器 ｜ 📋 复制该源的订阅链接 ｜ 🧪 立刻测一下 ｜ 🗑 删除。名称可直接点着改。

⚡ 订阅预热 / 定时刷新

日历 App 来取数据时如果边缘缓存是冷的，就得现抓源站（慢，还可能被限速）。这里可以先把缓存热上。「真正的定时刷新」用仓库里的 GitHub Actions（.github/workflows/warm-rss.yml）——因为 Cloudflare Pages 不支持 cron。

预热上面「📚 我的订阅源」里的全部订阅源：给每条链接加 fresh=1 打一次，强制刷新边缘缓存，日历 App 来取时就是热的。

⏰ 定时刷新怎么配（GitHub Actions）

1. 把要长期订阅的完整链接填进 .github/warm-rss.json 的 urls。

2. 提交推送。仓库里的 .github/workflows/warm-rss.yml 会每 2 小时自动给每条链接加 &fresh=1 打一次，把边缘缓存刷新。

3. 想立刻试：仓库 Actions → RSS 订阅缓存预热 → Run workflow（手动触发）。

⚠️ GitHub 的定时任务：仓库 60 天无活动会被自动停用，且高峰时段可能延迟几分钟到几十分钟。它不是"精确的秒级调度"。

⚠️ 上面的「本页打开期间自动预热」只在页面开着时生效，关掉页面就停。
